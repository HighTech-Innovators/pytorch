## Role

`caffe2/core` is the remaining minimal Caffe2 core shim that PyTorch still builds for legacy Caffe2 compatibility and shared configuration reporting. In this source tree it no longer contains the full historical Caffe2 runtime; it provides common includes and namespace aliases, build-option macros generated by CMake, an exported `GetBuildOptions()` function, and a small `Timer` utility. The directory preserves stable Caffe2-facing headers while modern tensor, dispatcher, and autograd functionality lives in c10, ATen, and torch/csrc.

## Key Files

| File | Purpose |
|---|---|
| `common.h` | Common Caffe2 header: standard-library includes, generated `macros.h`, c10 macro include, namespace aliases, platform handling, and `GetBuildOptions()` declaration |
| `common.cc` | Defines `caffe2::GetBuildOptions()` as a static map initialized from `CAFFE2_BUILD_STRINGS` |
| `macros.h` | Placeholder generated header included by `common.h` before build-time CMake substitution supplies real macro content |
| `macros.h.in` | CMake template defining Caffe2 feature macros and `CAFFE2_BUILD_STRINGS` entries used by `torch.__config__.show()` |
| `timer.h` | Header-only `caffe2::Timer` wrapper around `std::chrono::high_resolution_clock` with ns/us/ms/s accessors |
| `CMakeLists.txt` | Adds `common.cc` to `Caffe2_CPU_SRCS` and exports that list to the parent scope |

## Public Interface

The public C++ interface is `#include <caffe2/core/common.h>` for common Caffe2 types, generated feature macros, and `caffe2::GetBuildOptions()`. `GetBuildOptions()` returns `const std::map<std::string, std::string>&` and is exported with `TORCH_API`. `#include <caffe2/core/timer.h>` exposes `caffe2::Timer` with `Start()`, `NanoSeconds()`, `MicroSeconds()`, `MilliSeconds()`, and `Seconds()`. Build systems consume `macros.h.in` through CMake configure steps rather than including it directly.

## Dependencies

| Component | Direction | Nature |
|---|---|---|
| `c10/macros` | depends-on | Provides `TORCH_API` and `C10_DISABLE_COPY_AND_ASSIGN` used by `common.h` and `timer.h` |
| `CMake configuration` | depends-on | Generates `macros.h` content and `CAFFE2_BUILD_STRINGS` values from build options |
| [torch/csrc/profiler](torch/csrc/profiler/ADR.md) | related-to | `Timer` and build options support legacy diagnostics and configuration visibility used alongside modern profiling infrastructure |
| [c10/core](c10/core/ADR.md) | related-to | Modern tensor/runtime primitives live in c10; this directory only keeps legacy Caffe2 common utilities |

## Runtime Behaviour

At program startup, no active initialization occurs for this directory beyond normal static initialization on first `GetBuildOptions()` call. `GetBuildOptions()` creates a function-local static map from `CAFFE2_BUILD_STRINGS`; when the configured macro is absent, `common.cc` defines it as an empty initializer so the function still returns a valid map. `Timer` starts in its constructor, stores a `std::chrono::time_point`, and computes elapsed time by subtracting `start_time_` from `clock::now()` in each accessor.

## Performance Profile

`GetBuildOptions()` pays one lazy static map initialization and then returns a reference, so repeated configuration queries avoid copying the map. `Timer` is header-only and performs one `high_resolution_clock::now()` plus a duration cast per measurement, which is appropriate for testing utilities but not a replacement for PyTorch's structured profiler. The small directory contributes only `common.cc` to `Caffe2_CPU_SRCS`, keeping the legacy Caffe2 core footprint minimal compared with the dispatcher, ATen kernels, and autograd runtime.

## Design Rationale

PyTorch keeps this Caffe2 core layer to preserve include paths, exported build configuration, and lightweight testing utilities for code that still names the `caffe2` namespace. CMake owns feature macros because the values come from the configured build, compiler, CUDA/ROCm options, BLAS/LAPACK choices, and library toggles. The implementation delegates symbol visibility and copy-control macros to c10 instead of duplicating platform logic. This design lets legacy Caffe2-facing code compile while the real architecture described in the book chapters centers on c10 tensor primitives, ATen dispatch, and torch autograd.
