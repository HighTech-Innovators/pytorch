## Role

`caffe2/perfkernels` owns CPU-only fast paths for a small set of legacy Caffe2 kernels that still back ATen operators. In this tree it primarily specializes embedding-bag style reductions through ISA-dispatched inner loops and generated vector code.

## Key Files

| File | Purpose |
|---|---|
| `common.h` | Defines `SVE_DO`, `AVX512_DO`, `AVX2_DO`, `AVX2_FMA_DO`, `AVX_DO`, `AVX_F16C_DO`, and `BASE_DO` so entry points can dispatch by runtime CPU capability |
| `embedding_lookup_idx.h` | Declares the public `EmbeddingLookupIdx` template used by embedding bag callers |
| `embedding_lookup_idx.cc` | Defines the scalar fallback, macro-generated specializations, bounds checks, and ISA dispatch order |
| `embedding_lookup_idx_avx2.cc` | Autogenerated AVX2/FMA implementations for hot `EmbeddingLookupIdx_*__avx2_fma` specializations |
| `embedding_lookup_idx_sve.cc` | Autogenerated SVE implementations for `EmbeddingLookupIdx_*__sve` specializations |
| `hp_emblookup_codegen.py` | Generates the AVX2/FMA embedding lookup kernels with fixed-size unrolling and prefetch patterns |
| `sve_emblookup_codegen.py` | Generates the SVE embedding lookup kernels with predicated tail handling |
| `CMakeLists.txt` | Splits common, AVX2, and SVE translation units into separate static libraries with ISA-specific compile flags |

## Public Interface

The main public symbol is `caffe2::EmbeddingLookupIdx<IndexType, InType, OutType, IS_WEIGHT_POSITIONAL>` from `embedding_lookup_idx.h`. `common.h` also exports the dispatch macros `SVE_DO`, `AVX512_DO`, `AVX2_DO`, `AVX2_FMA_DO`, `AVX_DO`, `AVX_F16C_DO`, and `BASE_DO` for perfkernel entry points that follow the `foo__base` and `foo__isa` naming convention described in that header.

## Runtime Behaviour

`EmbeddingLookupIdx` specializations in `embedding_lookup_idx.cc` route each call through `SVE_DO`, then `AVX2_FMA_DO`, then `BASE_DO`, so the same API selects `EmbeddingLookupIdx_*__sve`, `EmbeddingLookupIdx_*__avx2_fma`, or the scalar fallback at runtime. The fallback implementation `EmbeddingLookupGenericSlowIdx` walks `offsets`, zeroes each output row with `memset`, checks every `indices[current]` bound, optionally prefetches the next embedding row, applies `weights` and optional `scale_bias`, and divides by segment length when `normalize_by_lengths` is true. The autogenerated AVX2 path in `embedding_lookup_idx_avx2.cc` hard-codes block-size cases such as 128, 64, and 32 elements so it can accumulate with `_mm256_fmadd_ps` registers and issue `_mm_prefetch` on future rows. The autogenerated SVE path in `embedding_lookup_idx_sve.cc` uses `svcntw()`, `svmla_x`, and `svwhilelt_b32_s64` so tail elements execute through predication instead of scalar cleanup code.

## Performance Profile

- **Allocation sites** — The kernels allocate no heap memory in their hot path. They operate directly on caller-owned `input`, `indices`, `offsets`, `weights`, `scale_bias`, and `out` buffers.
- **Synchronization costs** — Runtime ISA selection in `common.h` caches the `cpuinfo_initialize()` result in function-local `static const bool` flags, so later calls avoid repeated capability probes. The kernels themselves are single-threaded and add no locks or atomics.
- **Data movement** — The AVX2 and SVE variants stream contiguous embedding rows into vector registers and write each output row back once after accumulation or normalization. The scalar fallback also issues `__builtin_prefetch` in `EmbeddingLookupGenericSlowIdx` to hide the next row fetch on GCC builds.
- **Redundant or repeated work** — The fallback recomputes index validation on the error path after a failed optimized call so it can raise precise `CAFFE_ENFORCE` messages. The generated AVX2 code repeats specialized loops per block size to remove loop control overhead from the inner accumulation path.

## Design Rationale

This directory keeps perfkernels in separate translation units because `CMakeLists.txt` compiles AVX2 and SVE files with ISA-specific flags that must not leak into common code. The design exposes one stable `EmbeddingLookupIdx` template while hiding CPU feature dispatch and generated vector code behind predictable `__base`, `__avx2_fma`, and `__sve` symbol families. PyTorch still carries this Caffe2-era kernel because `aten/src/ATen/native/EmbeddingBag.cpp` uses it as a mature CPU fast path for embedding reductions instead of reimplementing the same specialization logic in ATen.
